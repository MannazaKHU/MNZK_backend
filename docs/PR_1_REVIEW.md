## 판단

점수 생성 책임을 AI에서 코드로 옮기고, 개인별 선호·비선호·필수 조건과 근거 상태를
구분한 방향은 현재 백엔드에 반영할 수 있습니다. 아래 재현된 문제를 수정하고 전체 테스트를 통과했습니다.
가중치의 경험적 타당성이나 실제 외부 데이터 품질까지 검증했다는 의미는 아닙니다.

## 발견 사항과 수정

| 우선순위 | 발견한 동작 | 재현 / 영향 | 수정 |
|---|---|---|---|
| P1 | 수정한 `conditions`가 후보 검색에 반영되지 않음 | 원문은 파스타, 확인 조건은 카페여도 검색어가 파스타로 생성됨. 평가할 후보부터 사용자 선택과 달라짐 | 구조화 조건이 있으면 검색·요약·점수 모두 이를 기준으로 사용. `conditions: []`도 존중. 명시한 조건은 AI로 다시 해석하지 않음 |
| P2 | AI 조건의 의미 검증 오류가 통제되지 않음 | 수량은 있지만 단위가 없는 출력이 JSON 구조 검증을 통과한 뒤 Pydantic 예외로 500이 됨. 원문과 맞지 않는 조건은 조용히 버려질 수 있음 | 수량·단위와 원문 인용을 검증하고 `502 AI_ERROR`로 처리. 잘못된 조건을 제외한 채 제출 완료로 저장하지 않음 |
| P2 | 지도 연동 단계에서 이동 시간을 반올림 | 1.51분과 2.49분이 모두 2분이 되어 다른 장소의 점수가 같아지고 ID 순으로 순위가 결정됨 | 실제 Directions 밀리초를 소수 분으로 유지. 1분 하한도 제거. 거리의 표시용 반올림은 유지 |
| P2 | 기존 네이버 진단 테스트가 로컬 `.env`에 의존 | `.env` 없는 worktree/새 checkout에서 전체 테스트 중 1개 실패 | 테스트 자체 임시 `.env`를 사용하도록 경로 주입. 실제 개발용 키와 무관하게 검증 |

개인별 서로 다른 의견과 OR 대안은 유지합니다. 구조화 조건이 없는 기존 데이터의 검색 필드는 계속 지원합니다.

## 점수 정책 확인

- 기본 가중치: 이동 D 0.4, 선호 P 0.3, 비선호 회피 N 0.3.
- 이동 점수: `clamp(100 × (1 − (0.5 × 평균 분 + 0.5 × 최대 분) / 60), 0, 100)`.
- P/N은 조건 → 종류별 평균 → 참여자별 평균 → 그룹 평균 순으로 계산합니다.
  P 또는 N이 없는 경우 해당 항목을 빼고 나머지 가중치를 재조정합니다.
- 일반 조건의 직접 근거는 100/0, 유효한 후기 추정은 75/25, 미확인은 50입니다.
  필수 조건은 가점으로 계산하지 않고 통과·제외·확인 필요 자격을 결정합니다.
- 한 명이라도 이동 시간이 없으면 점수와 순위를 만들지 않습니다. 직선거리나 0분으로 대체하지 않습니다.
- 정책 버전·원점수·가중치·기여분·근거 상태를 응답에 보존합니다. 점수는 만족 확률이 아닙니다.

  `ENABLE_BLOG_ENRICHMENT=true`나 키 추가만으로 검색이 시작되지는 않습니다.

  소수 점수를 화면에서만 적절히 표시해야 합니다.
- 40/30/30 가중치, 60분 기준, 미확인 50점·후기 75/25점, 후기 180일 정책은
  사용자 사례와 교수님 피드백에 따라 추가로 조정할 대상입니다.
